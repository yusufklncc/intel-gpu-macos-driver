2. SIP, AMFI, quirks and the console setting (config.plist)

The EFI partition is a small FAT32 partition, which every system can mount:

SystemMount the EFI partition
Windowsin an administrator Command Prompt: mountvol S: /S, then start ProperTree from the same prompt and open S:\EFI\OC\config.plist; mountvol S: /D when done
Linuxlsblk -o NAME,FSTYPE,PARTTYPENAME shows it (vfat, type "EFI System"), then sudo mount /dev/nvme0n1p1 /mnt with your partition
macOSdiskutil list shows it (EFI on the disk you boot from), then sudo diskutil mount disk0s1 with your partition

On Windows, IntelXe-EFI.ps1 in the -efi.zip makes items 1 to 5 for you in an EFI folder you choose (a USB stick's, or the EFI partition, which it can mount): right-click > Run with PowerShell, Settings: plan, then Settings: apply. It backs up the whole EFI folder first, keeps the rest of config.plist as it is, and can undo the change; see README-Windows.md in the zip. Its test suite passes on Windows; the window itself has not yet been used on an EFI that a PC then booted. On macOS on the PC, the IntelXe Manager app's EFI page (Change these settings) or sudo ./efi.sh --settings-apply from the macOS package make the same changes in the EFI OpenCore booted from (see 3.1).

In config.plist:

  1. Booter > Quirks > ResizeAppleGpuBars = 10. macOS cannot map the card's 16 GB BAR; this gives it a 1 GB window.
  2. Kernel > Quirks > DisableIoMapper = true.
  3. NVRAM > Add > 7C436110-AB2A-4BBB-A880-FE41995C9F82:
    • csr-active-config = 03080000 (Data): SIP relaxed, so that unsigned kexts load from the Auxiliary Kernel Collection;
    • boot-args: add amfi_get_out_of_my_way=0x1 (otherwise WindowServer refuses the unsigned Metal driver) and intelxe_surfvram=2 (IOSurfaces shared in VRAM between processes).
  4. NVRAM > Delete > 7C436110-AB2A-4BBB-A880-FE41995C9F82 must list csr-active-config and boot-args (Dortania's sample config does), so that the new values replace the old ones.
  5. UEFI > Output > ReconnectGraphicsOnConnect = false. With true, OpenCore's RELEASE build sets up the console before the card's firmware display (GOP) is back from the reconnect; macOS then boots without a console framebuffer, Lilu never completes its start, VirtualSMC's SMC device is not hooked up, and watchdogd panics the boot about 20 seconds in. OpenCore's DEBUG build is slow enough to hide this.
  6. For the system-volume copy (Safari on the GPU, 3.3): Misc > Security > SecureBootModel = Disabled.

Reboot into macOS. The screen still runs on the firmware output.

2. SIP, AMFI, quirk'ler ve konsol ayarı (config.plist)

EFI bölümü küçük bir FAT32 bölümü, her sistem bağlayabilir:

SistemEFI bölümünü bağlamak
WindowsYönetici olarak açılmış Komut İstemi'nde mountvol S: /S, ardından aynı pencereden ProperTree'yi başlatıp S:\EFI\OC\config.plist dosyasını açın; bitince mountvol S: /D
Linuxlsblk -o NAME,FSTYPE,PARTTYPENAME bölümü gösterir (vfat, tür "EFI System"), sonra kendi bölümünüzle sudo mount /dev/nvme0n1p1 /mnt
macOSdiskutil list bölümü gösterir (açılış diskinizdeki EFI), sonra kendi bölümünüzle sudo diskutil mount disk0s1

Windows'ta -efi.zip'teki IntelXe-EFI.ps1 1-5. maddeleri seçtiğiniz EFI klasöründe (bir USB belleğinkinde ya da bağlayabildiği EFI bölümünde) sizin yerinize yapar: sağ tık > PowerShell ile Çalıştır, Settings: plan, ardından Settings: apply. Önce EFI klasörünün tamamını yedekler, config.plist'in geri kalanını olduğu gibi bırakır ve değişikliği geri alabilir; zip'teki README-Windows.md'ye bakın. Deneme takımı Windows'ta hatasız geçiyor; pencerenin kendisi henüz ardından bir bilgisayarın açıldığı bir EFI'de kullanılmadı. Bilgisayardaki macOS'ta IntelXe Manager uygulamasının EFI sayfası (Bu ayarları değiştir) ya da macOS paketindeki sudo ./efi.sh --settings-apply aynı değişiklikleri OpenCore'un açıldığı EFI'de yapar (bkz. 3.1).

config.plist'te:

  1. Booter > Quirks > ResizeAppleGpuBars = 10. macOS, kartın 16 GB'lık BAR'ını eşleyemiyor; bu ayar 1 GB'lık bir pencere açıyor.
  2. Kernel > Quirks > DisableIoMapper = true.
  3. NVRAM > Add > 7C436110-AB2A-4BBB-A880-FE41995C9F82 altında:
    • csr-active-config = 03080000 (Data): imzasız kext'ler Yardımcı Kernel Koleksiyonu'ndan yüklenebilsin diye SIP gevşetiliyor;
    • boot-args'a amfi_get_out_of_my_way=0x1 (yoksa WindowServer imzasız Metal sürücüsünü reddediyor) ve intelxe_surfvram=2 (süreçler arasında VRAM'de paylaşılan IOSurface'ler) ekleyin.
  4. NVRAM > Delete > 7C436110-AB2A-4BBB-A880-FE41995C9F82 listesinde csr-active-config ve boot-args olmalı (Dortania'nın örnek yapılandırmasında var); yeni değerler eskilerin yerine böyle geçiyor.
  5. UEFI > Output > ReconnectGraphicsOnConnect = false. Bu ayar true olursa OpenCore'un RELEASE sürümü, kartın UEFI ekran sürücüsü (GOP) yeniden bağlanmadan konsolu kurmaya çalışıyor. macOS konsol ekranı olmadan açılıyor, Lilu başlatmasını tamamlayamıyor, VirtualSMC'nin SMC aygıtı bağlanmıyor ve watchdogd açılışın yaklaşık 20. saniyesinde panik veriyor. OpenCore'un DEBUG sürümü yavaş olduğu için bu sorunu gizliyor.
  6. Sistem diski kopyası için (GPU'da Safari, 3.3): Misc > Security > SecureBootModel = Disabled.

macOS'u yeniden başlatın. Ekran hâlâ UEFI çıktısında çalışır.
