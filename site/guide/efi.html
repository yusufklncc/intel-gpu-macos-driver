The EFI by handEFI'yi elle düzenlemek

Most people let a tool make these changes: the Windows app, IntelXe-EFI.ps1 on Windows, or the app's EFI page and efi.sh on macOS. This page is for doing it by hand: it lists every entry the tools write in the OpenCore EFI, exactly as they write it. Use any config.plist editor, from any system.Bu değişiklikleri çoğu kişi bir araca yaptırır: Windows uygulaması, Windows'ta IntelXe-EFI.ps1 ya da macOS'ta uygulamanın EFI sayfası ve efi.sh. Bu sayfa işi elle yapmak isteyenler için: araçların OpenCore EFI'sine yazdığı her kaydı, araçların yazdığı biçimde listeler. Stage 2: SIP, AMFI, quirks and the console setting2. aşama: SIP, AMFI, quirk'ler ve konsol ayarı

In config.plist, set these entries:

  1. Booter > Quirks > ResizeAppleGpuBars = 10. OpenCore's ocvalidate warns about this value. The warning is expected; keep 10.
    Why 10, and OpenCore's warning

    macOS cannot map the card's 16 GB BAR; this gives it a 1 GB window.

    ocvalidate reports this value as "unstable with macOS sleep-wake". The card forgets its BAR size in sleep, and macOS does not set it again; Apple's own GPU drivers do not handle this. IntelXe.kext sets it again on wake, as Linux does, and sleep works on the test machine.

    9 gets the same warning with half the window. 0, the value ocvalidate accepts, works too, but its 256 MB window is too small for the desktop and a game. Details: docs/design/DESIGN-rebar-window.md in the source repository.

  2. Kernel > Quirks > DisableIoMapper = true.
  3. NVRAM > Add > 7C436110-AB2A-4BBB-A880-FE41995C9F82:
    • csr-active-config = 03080000 (Data);
    • boot-args: add amfi_get_out_of_my_way=0x1 and intelxe_surfvram=2.
    What these values do
    • 03080000 relaxes SIP, so that unsigned kexts load from the Auxiliary Kernel Collection.
    • Without amfi_get_out_of_my_way=0x1, WindowServer refuses the unsigned Metal driver.
    • intelxe_surfvram=2: IOSurfaces shared in VRAM between processes.
  4. NVRAM > Delete > 7C436110-AB2A-4BBB-A880-FE41995C9F82 must list csr-active-config and boot-args, so that the new values replace the old ones. Dortania's sample config does.
  5. UEFI > Output > ReconnectGraphicsOnConnect = false.
    Why?

    With true, OpenCore's RELEASE build sets up the console before the card's firmware display (GOP) is back from the reconnect. macOS then boots without a console framebuffer. Lilu never completes its start, VirtualSMC's SMC device is not hooked up, and watchdogd panics the boot about 20 seconds in. OpenCore's DEBUG build is slow enough to hide this.

  6. For the system-volume copy (Safari on the GPU, Optional extras): Misc > Security > SecureBootModel = Disabled.

Reboot into macOS. The screen still runs on the firmware output. Then install the driver (From macOS). Come back for stage 4 before the next reboot.

config.plist'te şu kayıtları ayarlayın:

  1. Booter > Quirks > ResizeAppleGpuBars = 10. OpenCore'un ocvalidate aracı bu değer için uyarı verir. Bu uyarı beklenen bir durum; değeri 10'da bırakın.
    Neden 10 ve OpenCore'un uyarısı

    macOS, kartın 16 GB'lık BAR'ını eşleyemiyor; bu ayar 1 GB'lık bir pencere açıyor.

    ocvalidate bu değer için "unstable with macOS sleep-wake" uyarısı veriyor. Kart uykuda BAR boyutunu unutuyor ve macOS onu yeniden ayarlamıyor; Apple'ın kendi GPU sürücüleri bununla başa çıkamıyor. IntelXe.kext, Linux'un yaptığı gibi, uyanırken boyutu yeniden ayarlıyor ve test makinesinde uyku çalışıyor.

    9 da aynı uyarıyı alıyor, üstelik pencere yarıya iniyor. ocvalidate'in kabul ettiği 0 da çalışıyor ama 256 MB'lık penceresi masaüstü ve bir oyun için küçük kalıyor. Ayrıntılar: kaynak deposunda docs/design/DESIGN-rebar-window.md.

  2. Kernel > Quirks > DisableIoMapper = true.
  3. NVRAM > Add > 7C436110-AB2A-4BBB-A880-FE41995C9F82 altında:
    • csr-active-config = 03080000 (Data);
    • boot-args'a amfi_get_out_of_my_way=0x1 ve intelxe_surfvram=2 ekleyin.
    Bu değerler ne işe yarar
    • 03080000 SIP'i gevşetir; imzasız kext'ler böylece Yardımcı Kernel Koleksiyonu'ndan yüklenebilir.
    • amfi_get_out_of_my_way=0x1 olmazsa WindowServer imzasız Metal sürücüsünü reddeder.
    • intelxe_surfvram=2: süreçler arasında VRAM'de paylaşılan IOSurface'ler.
  4. NVRAM > Delete > 7C436110-AB2A-4BBB-A880-FE41995C9F82 listesinde csr-active-config ve boot-args olmalı; yeni değerler ancak böyle eskilerin yerine geçer. Dortania'nın örnek yapılandırmasında bu ikisi var.
  5. UEFI > Output > ReconnectGraphicsOnConnect = false.
    Neden?

    Bu ayar true olursa OpenCore'un RELEASE derlemesi, kartın UEFI ekran sürücüsü (GOP) yeniden bağlanmadan konsolu kurmaya çalışıyor. macOS konsol framebuffer'ı olmadan açılıyor. Lilu başlangıcını tamamlayamıyor, VirtualSMC'nin SMC aygıtı bağlanmıyor ve watchdogd açılışın yaklaşık 20. saniyesinde panik veriyor. OpenCore'un DEBUG derlemesi bu sorunu gizleyecek kadar yavaş.

  6. Sistem diski kopyası için (GPU'da Safari, İsteğe bağlı ekler): Misc > Security > SecureBootModel = Disabled.

macOS'u yeniden başlatın. Ekran hâlâ UEFI çıktısında çalışır. Sonra sürücüyü kurun (macOS'tan). Bir sonraki yeniden başlatmadan önce 4. aşama için buraya dönün.

Stage 4: IntelXe.kext4. aşama: IntelXe.kext

After the driver is installed, before the next macOS boot.

  1. Take the files from intel-gpu-macos-driver-0.1.7-efi.zip. The macOS package has the same files under EFI/OC/.
  2. Mount the EFI partition as above. On the PC itself: sudo diskutil mount disk0s1, with your partition.
  3. Copy IntelXe.kext to EFI/OC/Kexts/.
  4. Add it under Kernel > Add: BundlePath IntelXe.kext, ExecutablePath Contents/MacOS/IntelXe, PlistPath Contents/Info.plist, Enabled true.

This is the GPU driver. It does not need Lilu.

What is inside IntelXe.kext?

The GPU driver, with the GPU's GuC/HuC firmware included.

Sürücü kurulduktan sonra, macOS bir daha açılmadan önce.

  1. Dosyaları intel-gpu-macos-driver-0.1.7-efi.zip'ten alın. macOS paketinde de EFI/OC/ altında aynıları var.
  2. EFI bölümünü yukarıdaki gibi bağlayın. Kurulacak bilgisayarın kendisindeyseniz bölüm adını kendinizinkiyle değiştirerek sudo diskutil mount disk0s1 komutunu çalıştırın.
  3. IntelXe.kext'i EFI/OC/Kexts/ klasörüne kopyalayın.
  4. Kernel > Add altına ekleyin: BundlePath IntelXe.kext, ExecutablePath Contents/MacOS/IntelXe, PlistPath Contents/Info.plist, Enabled true.

Bu, GPU sürücüsünün kendisidir. Lilu gerektirmez.

IntelXe.kext'in içinde ne var?

GPU sürücüsü; GPU'nun GuC/HuC firmware'i de içindedir.

Stage 4: SSDT-ARCOFF and your card's ACPI path4. aşama: SSDT-ARCOFF ve kartınızın ACPI yolu

SSDT-ARCOFF.aml hides the card from macOS's generic display driver. Its ACPI path depends on the board.

Why hide the card, and what the shipped path means

On Tahoe, that driver otherwise takes the card, and the IntelXe kexts cannot start.

The shipped table is for a board whose ACPI names the slot's root port \_SB.PC00.PEG1 and the card's own PCIe switch below it PEGP. Below PEGP every B580 looks the same: a downstream port at PCI(0100), then the GPU at PCI(0000).

  1. Find your card's ACPI path:

SSDT-ARCOFF.aml, kartı macOS'un genel ekran sürücüsünden gizler. ACPI yolu anakarta göre değişir.

Kart neden gizleniyor, paketteki yol ne anlama geliyor

Gizlenmezse Tahoe'da kartı o sürücü alır ve IntelXe kext'leri başlayamaz.

Paketteki tablo, yuvanın kök portunu \_SB.PC00.PEG1, kartın kendi PCIe anahtarını da onun altında PEGP diye adlandıran bir anakart için. PEGP'nin altı her B580'de aynı: PCI(0100)'de bir alt port, PCI(0000)'da GPU.

  1. Kartınızın ACPI yolunu bulun:

On a hybrid Intel CPU, add HybridPM next (below). Otherwise, reboot and check.

Hibrit bir Intel işlemciniz varsa sırada HybridPM var (aşağıda). Yoksa yeniden başlatın ve kontrol edin.

Hybrid Intel CPUs (12th-14th gen): HybridPM.kextHibrit Intel işlemciler (12.-14. nesil): HybridPM.kext

On these CPUs, macOS's power management holds the cores back, and the GPU looks slow too. HybridPM.kext fixes that. HybridPM is separate from the GPU driver and optional. It is in the -efi.zip and in the macOS package under EFI/OC/Kexts/.

Why the CPU makes the GPU look slow

macOS's CPU power management (XCPM) predates CPUs with performance and efficiency cores. On Alder Lake and Raptor Lake it caps the P-cores (an i7-14700K stayed at 4.4 GHz instead of 5.6) and can hold fully busy cores at 800 MHz. The GPU driver does a lot of CPU work per command buffer, so the GPU looks slow too. On the test machine Geekbench's GPU scores were about a third higher with HybridPM.kext, and one CPU thread more than twice as fast.

Which CPUs: 12th, 13th and 14th generation Core i3/i5/i7/i9 with P- and E-cores, and Core Ultra 200S desktop CPUs. On a Core Ultra 200S, add it by hand.

Which CPUs exactly

12th, 13th and 14th generation Core i3/i5/i7/i9 with P- and E-cores (Alder Lake and Raptor Lake, desktop and laptop; e.g. i5-12600K, i5-13400F, i7-14700K, i7-13620H), and Core Ultra 200S desktop CPUs (Arrow Lake, e.g. Core Ultra 7 265K; measured by a contributor, not on the test machine). Other Core Ultra CPUs, CPUs without E-cores and older CPUs it leaves alone (it only logs why). The install tools go by the CPU's name and do not add it on a Core Ultra yet: on Arrow Lake, add it by hand. The model list is in kernel/HybridPM/README.md in the repository.

On the PC, stage 4 adds it for you: efi.sh --plan / sudo ./efi.sh --apply and the app's EFI page copy HybridPM.kext with IntelXe.kext when the CPU's name is one of these.

What the tools do with HybridPM

They add its entry right below Lilu.kext's. An existing entry is turned on; an earlier build under the same name is replaced. They leave it out, with a note, when the EFI does not load Lilu. IntelXe-EFI.ps1 on Windows does the same, by the CPU of the PC it runs on.

By hand:

  1. Your EFI needs Lilu.kext: HybridPM is a Lilu plugin. Most OpenCore EFIs already have it for VirtualSMC. If yours has not, add it from acidanthera/Lilu. This package does not include Lilu.
  2. Copy HybridPM.kext to EFI/OC/Kexts/.
  3. Add it under Kernel > Add, below Lilu.kext: BundlePath HybridPM.kext, ExecutablePath Contents/MacOS/HybridPM, PlistPath Contents/Info.plist, Enabled true.
  4. Reboot. It starts working 20 seconds after boot.

How far this was tested: Lilu 1.7.2 was used on the test machine. IntelXe-EFI.ps1 adding HybridPM was not yet run on Windows.

Bu işlemcilerde macOS'un güç yönetimi çekirdekleri frenliyor, bu yüzden GPU da yavaş görünüyor. HybridPM.kext bunu düzeltiyor. HybridPM GPU sürücüsünden ayrıdır ve isteğe bağlıdır. -efi.zip'te ve macOS paketinin EFI/OC/Kexts/ klasöründe bulunur.

İşlemci neden GPU'yu yavaş gösteriyor

macOS'un işlemci güç yönetimi (XCPM), performans ve verimlilik çekirdekleri olan işlemcilerden önce yazıldı. Alder Lake ve Raptor Lake'te P çekirdeklerini sınırlıyor (bir i7-14700K 5,6 yerine 4,4 GHz'de kaldı) ve tam yüklü çekirdekleri 800 MHz'de tutabiliyor. GPU sürücüsü her komut arabelleği için işlemcide epey iş yapıyor, bu yüzden GPU da yavaş görünüyor. Test makinesinde Geekbench'in GPU puanları HybridPM.kext ile yaklaşık üçte bir daha yüksek çıktı, tek bir işlemci iş parçacığı da iki kattan fazla hızlandı.

Hangi işlemciler: P ve E çekirdekli 12., 13. ve 14. nesil Core i3/i5/i7/i9 ile Core Ultra 200S masaüstü işlemciler. Core Ultra 200S'te HybridPM'i elle eklemeniz gerekir.

Tam olarak hangi işlemciler

P ve E çekirdekli 12., 13. ve 14. nesil Core i3/i5/i7/i9 (Alder Lake ve Raptor Lake, masaüstü ve dizüstü; örneğin i5-12600K, i5-13400F, i7-14700K, i7-13620H) ve Core Ultra 200S masaüstü işlemciler (Arrow Lake, örneğin Core Ultra 7 265K; bir katkıda bulunan ölçtü, test makinesinde değil). HybridPM öteki Core Ultra'lara, E çekirdeği olmayan işlemcilere ve daha eski işlemcilere dokunmaz (yalnızca nedenini günlüğe yazar). Kurulum araçları işlemcinin adına baktıkları için bir Core Ultra'da HybridPM'i henüz eklemez: Arrow Lake'te elle ekleyin. Model listesi depodaki kernel/HybridPM/README.md dosyasında.

Bilgisayarın kendisinde 4. aşama HybridPM'i sizin yerinize ekler: efi.sh --plan / sudo ./efi.sh --apply ve uygulamanın EFI sayfası, işlemcinin adı bunlardan biriyse HybridPM.kext'i IntelXe.kext ile birlikte kopyalar.

Araçlar HybridPM'le ne yapar

Kaydını Lilu.kext'in kaydının hemen altına eklerler. Kayıt zaten varsa etkinleştirilir; aynı adlı eski bir derleme yenisiyle değiştirilir. EFI Lilu yüklemiyorsa HybridPM'i eklemezler ve bunu bir notla belirtirler. Windows'taki IntelXe-EFI.ps1 de çalıştığı bilgisayarın işlemcisine bakarak aynısını yapar.

Elle:

  1. EFI'nizde Lilu.kext olmalı: HybridPM bir Lilu eklentisidir. Çoğu OpenCore EFI'sinde VirtualSMC için Lilu.kext zaten var. Sizinkinde yoksa acidanthera/Lilu'dan ekleyin. Lilu bu pakette yok.
  2. HybridPM.kext'i EFI/OC/Kexts/ klasörüne kopyalayın.
  3. Kernel > Add içinde Lilu.kext'in altına ekleyin: BundlePath HybridPM.kext, ExecutablePath Contents/MacOS/HybridPM, PlistPath Contents/Info.plist, Enabled true.
  4. Yeniden başlatın. HybridPM açılıştan 20 saniye sonra devreye girer.

Ne kadar denendi: Test makinesinde Lilu 1.7.2 kullanıldı. IntelXe-EFI.ps1'in HybridPM'i eklemesi henüz Windows'ta hiç çalıştırılmadı.

Checking itKontrol etmek

sysctl debug.hybridpm.enabled debug.hybridpm.why debug.hybridpm.route

Expected outputBeklenen çıktı

debug.hybridpm.enabled: 1, debug.hybridpm.why: on (model 0xB7), debug.hybridpm.route: 1
./hpmstat 1000 3     # in the package folder: each core's clock and load, HWP limits, package power
./hpmstat 1000 3     # paket klasöründe: her çekirdeğin saati ve yükü, HWP sınırları, paket gücü
Got 0, or no debug.hybridpm at all?

With enabled 0, why says why: not hybrid or unsupported model (other Core Ultra CPUs and others), or route 3 when a macOS update changed the routine it corrects. macOS then runs as without it.

When debug.hybridpm does not exist, HybridPM or Lilu did not load. Check with kmutil showloaded | grep -i -e lilu -e hybridpm.

Turning it off: add -hpmoff to the boot-args, or set its Kernel > Add entry to Enabled false. Until the next restart, sudo sysctl debug.hybridpm.hwp=0 debug.hybridpm.autonomous=0 debug.hybridpm.epp=-1 debug.hybridpm.eet_off=0 gives back macOS's own settings.

0 mı çıktı, yoksa debug.hybridpm hiç mi yok?

enabled 0 ise nedeni why'da yazar: not hybrid ya da unsupported model (öteki Core Ultra'lar ve diğerleri); bir macOS güncellemesi HybridPM'in düzelttiği rutini değiştirdiyse route 3 görünür. Bu durumlarda macOS, HybridPM yokmuş gibi çalışır.

debug.hybridpm hiç yoksa HybridPM ya da Lilu yüklenmemiştir. kmutil showloaded | grep -i -e lilu -e hybridpm ile denetleyin.

Kapatmak: boot-args'a -hpmoff ekleyin ya da Kernel > Add kaydını Enabled false yapın. Bir sonraki yeniden başlatmaya kadar sudo sysctl debug.hybridpm.hwp=0 debug.hybridpm.autonomous=0 debug.hybridpm.epp=-1 debug.hybridpm.eet_off=0 macOS'un kendi ayarlarını geri getirir.

Then reboot and check the driver.
