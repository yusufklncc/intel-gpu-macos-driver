# User space

| Path | What |
|---|---|
| `xemac/` | The user-space side of IntelXe.kext's xe interface: `xemac_open`/`xemac_ioctl`/`xemac_mmap` in place of a DRM render node. It also contains a libdrm stand-in (`libdrm/xf86drm.h`, `xemac_drm.c`) and an `XEMAC_FAKE=1` device. Mesa is built with `-Dxemac=<repo>/user/xemac` (see `mesa/`). It opens the xe client through NMXAccel (an IOAccelerator, so sandboxed processes may use it), falling back to IntelXe.kext directly (`XEMAC_DIRECT=1` forces that). |
| `tests/kernel/` | uAPI tests without Mesa: `kxtest` (exec on every engine, load mode), `memq`, `vfill`, `vbw`, `vlat`, `rtt`, `bomove` (BO moves in and out of the BAR window; `bomove evict`), `winfill` (`unmap`: CPU maps are unmapped and distinct; `fill`: fills the CPU-visible window and checks that allocations, binds and contents still work), `latewake`, `surffence` (IOSurface fences), `surfvram` (VRAM-shared IOSurfaces), `ulls` and `direct_lat` (job start without and with the kext's direct submission, `debug.intelxe.direct`), `ufence` (user fences: every engine, `WAIT_USER_FENCE` ops, masks and timeouts, bind fences, a destroyed queue, back-to-back compute jobs); display tools `dmode` (`dmode W H [Hz]`: switches the mode for good, at a refresh rate if given), `fbcrop`; `vmouse` (virtual HID, needs `vmouse.ent`). Build: `clang -arch x86_64 -O1 -I../../../kernel/IntelXe/uapi -o X X.c -framework IOKit -framework CoreFoundation` |
| `tests/vulkan/` | `vk_smoke` (device + fill on every queue family), `vk_videocaps` (video profiles and queue families), `vkwin` (BAR-window cost of a VkDevice and of the plugin's descriptor pools, from `debug.intelxe.stats`); `build.sh` (needs Mesa's `include/`) |
| `tests/metal/` | `mtl_smoke`, `mtl_tests` (vadd, threadgroup/atomics, math, textures, blit, render, perf, `bw`, `mip`), `mtl_cube_read` (reads back every texel of every face, slice and level of cube, integer cube, cube-array and read-write cube textures), `mtl_props` (prints the device properties the plugin answers: registry, location and link rate, peers, feature queries, limits, sparse tiers), `mtl_f32filter` (linear filtering of R32/RG32/RGBA32 float textures gives the midpoint, as `supports32BitFloatFiltering` promises), `mtl_lat`, OpenCL `cl_img`/`cl_lat`/`cl_xfer`, `xlate_check` (offline AIR → SPIR-V), `mtl_pools` (descriptor pools: window cost per process, growth, the full-pools error, set reclaim, texel buffers), `svimg` (two-process VRAM-shared IOSurface image test), `gpt_bench` (frame loop for GPUTIME; `surf` checks IOSurface out/in), `mtl_order_stress` (command buffer ordering across queues and threads, for the plugin's commit locking), `plock_model` (a model of the lock V2 primitives, no GPU; `mtl_lat split` times the parts of one command buffer). `NVMTL_BUNDLE=<staged bundle>` tests a plugin build without installing it. `nullmoth/build/build-intelxe.sh tests` builds `mtl_smoke`, `xlate_check`, `mtl_cube_read`, `mtl_props` and `mtl_f32filter`. |
| `tests/inv/` | investigation tools and regression scripts from the bring-up of the accelerated desktop: present/IOSurface races (`burstpresent`, `surftest`), sampler/mip/pixelation (`samptest*`, `mipapp64`, `cgtest`, `citest`), OpenCL correctness/perf (`cl*`), GL (`glflat`, `glidx`), memory churn, the `final*.sh` gate scripts. Machine paths inside the scripts are those of the test machine. |
| `tests/gate/` | `gate.sh`: the post-reboot regression gate, run from the build Mac over `rsh` (time-boxed ssh; `INTELXE_HOST=user@machine`) |
| `tools/` | `sigcheck.c` (is every Mach-O code-signed? no Apple tools needed on the test machine); `install-plugin.sh`, `install-plugin-mesa.sh`, `install-plugin-lib.sh`: the guarded install scripts of a staged plugin (and Mesa) build: SHA256SUMS and signature checks, a backup in `./previous/`, `--undo` |
| `tools/ssv-install.sh`, `tools/ssv-watch/` | the optional system-volume copy of the Metal driver (Safari WebGL) and the service that offers to reinstall it after a macOS update |
| `vulkan-loader/` | notes, install script and check program for the Khronos Vulkan loader with our ICD manifest |
| `tests/cts/`, `tests/stability/`, `tests/wsi/`, `tests/wine/`, `tests/plugin/` | the Vulkan CTS runner and result parser; hang, sleep and leak loops (`vkhang`, `hangsuite.sh`, `sleeptest.sh`); presentation tests; Wine/DXVK/VKD3D runs; plugin bisect and comparison scripts |
| `tests/compute/` | `ze_hello` (Level Zero through Intel's compute runtime, `compute/`): driver/device enumeration, USM, copy-engine fill and copy, `compute` (NEO's built-in kernels from files), `kernel <bin>` (a native kernel, e.g. `kernels/fill_ids.cl` compiled by `compute/ocloc-docker.sh`); `cl_hello` (Intel's OpenCL through the Khronos ICD loader: platform, buffer round trip, `kernel <bin>`); built and staged by `compute/build-neo.sh` (`OCL=1` for `cl_hello`) |
| `tests/igpu/` | `vttest` (VideoToolbox HW encode/decode + Metal device list), `devorder` (Metal/OpenCL device order) |

All tests are x86_64 binaries. They run on the test machine; on Apple Silicon only under Rosetta, and there without the GPU.
