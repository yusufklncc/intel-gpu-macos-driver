TroubleshootingSorun giderme

After installing or updatingKurulumdan ya da güncellemeden sonra

What changes when macOS or the driver changes: the Safari copy after a macOS update, the warnings IntelXe Manager shows after an install, and the steps from each earlier build to 0.1.6.macOS ya da sürücü değişince ne değişiyor: macOS güncellemesinden sonra Safari kopyası, kurulumdan sonra IntelXe Manager'ın gösterdiği uyarılar ve eski her sürümden 0.1.6'ya geçiş adımları.

After a macOS update: Safari is slow againmacOS güncellemesinden sonra: Safari yine yavaş

macOS updates can be installed: the driver in /Library stays. An update replaces the system volume, and with it the system-volume copy that Safari's GPU process loads (./ssv-install.sh --check says so). The app notices (with the optional check at login, in one dialog) and its Driver page (Safari and WebKit) installs the copy again; in Terminal, sudo ./system-volume/ssv-install.sh --apply in the package folder. More on the copy: Safari on the GPU. A macOS update can also change the routine HybridPM corrects; it then stands aside (route 3, checking HybridPM).

macOS güncellemeleri kurulabilir: /Library'deki sürücü yerinde kalıyor. Güncelleme sistem diskini ve onunla birlikte Safari'nin GPU sürecinin yüklediği sistem diski kopyasını değiştiriyor (./ssv-install.sh --check bunu söyler). Uygulama bunu fark ediyor (isteğe bağlı giriş kontrolüyle tek bir pencerede) ve Sürücü sayfası (Safari ve WebKit) kopyayı yeniden kuruyor; Terminal'de paket klasöründe sudo ./system-volume/ssv-install.sh --apply. Kopya hakkında daha fazlası: GPU'da Safari. Bir macOS güncellemesi HybridPM'in düzelttiği rutini de değiştirebilir; o zaman HybridPM kenara çekilir (route 3, HybridPM'i kontrol etmek).

"The system-volume copy is older than the rest""Sistem diski kopyası geri kalanından eski"

WindowServer uses the copy on the system volume, and it is from an earlier release. Install the package's system-volume copy too (the Driver page, or sudo ./system-volume/ssv-install.sh --apply) and restart. After an upgrade, install.sh --apply may have created /Library/GPUBundles/NVMTLDriver.use-library so that every process uses the /Library copy in the meantime; from 0.1.6 installing the new copy (from the app or with ssv-install.sh --apply) removes it again. With 0.1.5 and earlier, after ssv-install.sh --apply run sudo rm /Library/GPUBundles/NVMTLDriver.use-library.

WindowServer sistem diskindeki kopyayı kullanıyor ve o daha eski bir sürümden. Paketin sistem diski kopyasını da kurun (Sürücü sayfası ya da sudo ./system-volume/ssv-install.sh --apply) ve yeniden başlatın. Bir yükseltmeden sonra install.sh --apply, o arada her süreç /Library kopyasını kullansın diye /Library/GPUBundles/NVMTLDriver.use-library dosyasını oluşturmuş olabilir; 0.1.6'dan itibaren yeni kopyayı kurmak (uygulamadan ya da ssv-install.sh --apply ile) onu yeniden siler. 0.1.5 ve öncesinde ssv-install.sh --apply'dan sonra sudo rm /Library/GPUBundles/NVMTLDriver.use-library çalıştırın.

"IntelXe.kext X is loaded, but Y is installed""IntelXe.kext X yüklü, ama Y kurulu"

The kernel still runs the previous build. Restart; if the warning stays, run Install this package again on the Driver page, and update IntelXe.kext on the EFI page (it lives in the EFI, so the package install alone does not replace it). After an install the app compares the EFI's IntelXe.kext with the package's and warns only when they differ, the kext or its entry is missing or off, or the EFI could not be read.

Çekirdek hâlâ önceki derlemeyi çalıştırıyor. Yeniden başlatın; uyarı kalırsa Sürücü sayfasında Bu paketi kur'u yeniden çalıştırın ve EFI sayfasında IntelXe.kext'i güncelleyin (EFI'de durduğu için yalnızca paketi kurmak onu değiştirmiyor). Uygulama kurulumdan sonra EFI'deki IntelXe.kext'i paketteki ile karşılaştırıyor; yalnızca farklıysa, kext ya da kaydı yoksa veya kapalıysa ya da EFI okunamadıysa uyarıyor.

Upgrading from an earlier buildEski bir sürümden yükseltme

Later releases install over the old one: the app's Driver page downloads the new release, checks its signature and installs it, then its EFI page replaces IntelXe.kext. What each earlier build needs:

Sonraki sürümler eskisinin üzerine kuruluyor: uygulamanın Sürücü sayfası yeni sürümü indiriyor, imzasını denetliyor ve kuruyor, sonra EFI sayfası IntelXe.kext'i değiştiriyor. Her eski sürümün gerektirdikleri:

From 0.1.50.1.5'ten

  1. Install the package (the app: Download v0.1.6, then Install this package; or sudo ./install.sh --apply).
  2. Replace IntelXe.kext in the EFI before you restart: the app's EFI page or sudo ./efi.sh --apply on macOS; on Windows IntelXe Manager for Windows (EFI page, IntelXe.kext and SSDT-ARCOFF (stage 4)) or IntelXe-EFI.ps1; or by hand. Its config.plist entry stays as it is. The same step replaces HybridPM.kext where it is used. The display boost is in IntelXe.kext: with 0.1.5's, NMXAccel's requests are only counted as failed (debug.nmxaccel_vbl_boost_fail).
  3. If you installed the system-volume copy for Safari, install this package's too (the app's Driver page, Safari and WebKit; or sudo ./system-volume/ssv-install.sh --apply): 0.1.6 changes the Metal driver. Until then install.sh --apply makes every process use the /Library copy (NVMTLDriver.use-library), and ssv-install.sh --apply removes that file again, also one that 0.1.5's install.sh left behind; one you made yourself stays (Safari on the GPU). No sudo rm by hand.
  4. Restart.

To go back to 0.1.5's behaviour for one of the changes only: NVMTL_SCANOUT_READBACK=1 in /Library/GPUBundles/nvmtl/nvrm610.conf (the full readback of every frame; WindowServer takes it at the next restart); -intelxe_nodispboost in the boot-args, or sudo sysctl debug.intelxe.disp_boost=0 until the next restart (the display boost); NVMTL_MESH_OBJECT=0 in the same file (object + mesh pipelines refused). If one of them fixes something, please send a report that names it.

  1. Paketi kurun (uygulamada v0.1.6 sürümünü indir, sonra Bu paketi kur; ya da sudo ./install.sh --apply).
  2. Yeniden başlatmadan önce EFI'deki IntelXe.kext'i değiştirin: macOS'ta uygulamanın EFI sayfası ya da sudo ./efi.sh --apply; Windows'ta Windows için IntelXe Manager (EFI sayfası, IntelXe.kext ve SSDT-ARCOFF (4. aşama)) ya da IntelXe-EFI.ps1; ya da elle. config.plist kaydı olduğu gibi kalır. Kullanılıyorsa HybridPM.kext'i de aynı adım değiştirir. Ekran hızlandırması IntelXe.kext'in içinde: 0.1.5'inkiyle NMXAccel'in istekleri yalnızca başarısız diye sayılır (debug.nmxaccel_vbl_boost_fail).
  3. Safari için sistem diski kopyasını kurduysanız bu paketinkini de kurun (uygulamanın Sürücü sayfası, Safari ve WebKit; ya da sudo ./system-volume/ssv-install.sh --apply): 0.1.6 Metal sürücüsünü değiştiriyor. O zamana kadar install.sh --apply bütün süreçlere /Library kopyasını kullandırır (NVMTLDriver.use-library); ssv-install.sh --apply bu dosyayı, 0.1.5'in install.sh'inin bıraktığını da, yeniden siler; sizin oluşturduğunuz kalır (GPU'da Safari). Elle sudo rm gerekmiyor.
  4. Yeniden başlatın.

Değişikliklerden yalnızca birinde 0.1.5'in davranışına dönmek için: /Library/GPUBundles/nvmtl/nvrm610.conf'ta NVMTL_SCANOUT_READBACK=1 (her karenin tam geri okunması; WindowServer bir sonraki yeniden başlatmada alır); boot-args'ta -intelxe_nodispboost ya da bir sonraki yeniden başlatmaya kadar sudo sysctl debug.intelxe.disp_boost=0 (ekran hızlandırması); aynı dosyada NVMTL_MESH_OBJECT=0 (object + mesh pipeline'ları reddedilir). Biri bir sorunu çözüyorsa lütfen onu adıyla belirten bir rapor gönderin.

From 0.1.40.1.4'ten

  1. Install the package (the app: Download v0.1.6, then Install this package; or sudo ./install.sh --apply).
  2. Replace IntelXe.kext in the EFI before you restart: the app's EFI page or sudo ./efi.sh --apply on macOS; on Windows IntelXe Manager for Windows (EFI page, IntelXe.kext and SSDT-ARCOFF (stage 4)) or IntelXe-EFI.ps1; or by hand. Its config.plist entry stays as it is. The same step replaces HybridPM.kext where it is used.
  3. If you installed the system-volume copy for Safari, install this package's too (the app's Driver page, Safari and WebKit; or sudo ./system-volume/ssv-install.sh --apply).
  4. Restart.

0.1.5 changes four defaults: direct submission is on, the Metal driver uses the descriptor-buffer model for applications (WindowServer stays on the classic model), video decoding goes straight through Vulkan Video for H.264, HEVC, AV1 and VP9 (libavcodec only for what that path does not cover), and the encoders upload through the copy engine. This release ran on the B580 with all four on. If video, a Metal app or a Vulkan program misbehaves, go back to 0.1.4's behaviour for that one default and please send a report: -intelxe_nodirect in the boot-args (job submission); and in /Library/GPUBundles/nvmtl/nvrm610.conf, one line each, NVMTL_DESC_MODEL=classic (the descriptor model), INTELXEDEC_DIRECT=0 (video decoding through libavcodec; a list such as h264,hevc keeps only those codecs direct), INTELXEVENC_UPLOAD=copy (the encoders' CPU copy). Processes started afterwards take them. 0.1.6's changes come on top, with their own switches back (From 0.1.5).

  1. Paketi kurun (uygulamada v0.1.6 sürümünü indir, sonra Bu paketi kur; ya da sudo ./install.sh --apply).
  2. Yeniden başlatmadan önce EFI'deki IntelXe.kext'i değiştirin: macOS'ta uygulamanın EFI sayfası ya da sudo ./efi.sh --apply; Windows'ta Windows için IntelXe Manager (EFI sayfası, IntelXe.kext ve SSDT-ARCOFF (4. aşama)) ya da IntelXe-EFI.ps1; ya da elle. config.plist kaydı olduğu gibi kalır.   4. Yeniden başlatın.

0.1.5 dört varsayılanı değiştiriyor: doğrudan gönderim açık, Metal sürücüsü uygulamalar için tanımlayıcı arabelleği modelini kullanıyor (WindowServer klasik modelde kalıyor), video çözme H.264, HEVC, AV1 ve VP9 için doğrudan Vulkan Video üzerinden gidiyor (libavcodec yalnızca bu yolun kapsamadıkları için) ve kodlayıcılar kopyalama motoruyla yüklüyor. Bu sürüm dördü de açıkken B580'de çalıştı. Video, bir Metal uygulaması ya da bir Vulkan programı sorun çıkarırsa yalnızca o varsayılan için 0.1.4'ün davranışına dönün ve lütfen bir rapor gönderin: boot-args'ta -intelxe_nodirect (iş gönderimi); /Library/GPUBundles/nvmtl/nvrm610.conf'ta her biri bir satır olarak NVMTL_DESC_MODEL=classic (tanımlayıcı modeli), INTELXEDEC_DIRECT=0 (video çözme libavcodec üzerinden; h264,hevc gibi bir liste yalnızca o kodekleri doğrudan yolda tutar), INTELXEVENC_UPLOAD=copy (kodlayıcılarda işlemci kopyası). Sonradan başlayan süreçler bunları alır. 0.1.6'nın değişiklikleri de bunların üstüne geliyor, geri dönüş anahtarlarıyla birlikte (0.1.5'ten).

From 0.1.30.1.3'ten

As from 0.1.4, and what 0.1.4 brought: IntelXe.kext (in the EFI), IntelXeFB.kext, NMXAccel.kext and the Metal driver are new (lock V2, the translator fix, the B570's ID, the GPU clock and temperature readings, direct submission; 0.1.4 kept Mesa and the video codecs of 0.1.3, which 0.1.5 replaces). Install the package (the app: Download v0.1.6, then Install this package; or sudo ./install.sh --apply), then replace IntelXe.kext in the EFI before you restart (the app's EFI page or sudo ./efi.sh --apply on macOS, or IntelXe Manager for Windows or IntelXe-EFI.ps1 on Windows, which also add HybridPM.kext on a hybrid Intel CPU; or by hand; its config.plist entry stays as it is). If you installed the system-volume copy, install this package's too (the Driver page's Safari and WebKit, or sudo ./system-volume/ssv-install.sh --apply), so that Safari gets the new Metal driver.

The GuC low-latency hint that keeps the GPU clock up for apps is off by default from 0.1.4 (with it, a GPU fault followed a long idle in testing); the app's Power and app page (Fast GPU response for apps) or sudo touch /Library/GPUBundles/NVMTLDriver.low-latency turns it on. Direct submission was off as well in 0.1.4 (sudo sysctl debug.intelxe.direct=1 turned it on until the next restart); from 0.1.5 it is on by default (From 0.1.4).

0.1.4'ten olduğu gibi; ayrıca 0.1.4'ün getirdikleri: IntelXe.kext (EFI'de), IntelXeFB.kext, NMXAccel.kext ve Metal sürücüsü yeni (lock V2, çevirici düzeltmesi, B570'in kimliği, GPU saati ve sıcaklık okumaları, doğrudan gönderim; 0.1.4, 0.1.3'ün Mesa'sını ve video kodeklerini korumuştu, 0.1.5 onları da yeniliyor). Paketi kurun (uygulamada v0.1.6 sürümünü indir, sonra Bu paketi kur; ya da sudo ./install.sh --apply), sonra yeniden başlatmadan önce EFI'deki IntelXe.kext'i değiştirin (macOS'ta uygulamanın EFI sayfası ya da sudo ./efi.sh --apply, Windows'ta Windows için IntelXe Manager ya da IntelXe-EFI.ps1; hepsi hibrit bir Intel işlemcide HybridPM.kext'i de ekler; ya da elle; config.plist kaydı olduğu gibi kalır). Sistem diski kopyasını kurduysanız bu paketinkini de kurun (Sürücü sayfasında Safari ve WebKit ya da sudo ./system-volume/ssv-install.sh --apply); Safari yeni Metal sürücüsünü böyle alır.

Uygulamalar için GPU saatini yüksek tutan GuC düşük gecikme ipucu 0.1.4'ten beri varsayılan olarak kapalı (açıkken testlerde uzun bir boşta kalmanın ardından GPU hatası görüldü); uygulamanın Güç ve uygulama sayfası (Uygulamalar için hızlı GPU yanıtı) ya da sudo touch /Library/GPUBundles/NVMTLDriver.low-latency açar. 0.1.4'te doğrudan gönderim de kapalıydı (sudo sysctl debug.intelxe.direct=1 bir sonraki yeniden başlatmaya kadar açıyordu); 0.1.5'ten itibaren varsayılan olarak açık (0.1.4'ten).

From 0.1.20.1.2'den

As from 0.1.3, and NMXAGDC.kext, the video decoder and Mesa's Vulkan driver are new too (refresh rates above the firmware's, Adaptive-Sync modes on by default, the optional HiDPI modes at the full refresh rate, full-range video decoded as full range, WindowServer keeping its compiled shaders). If you installed the system-volume copy, install.sh --apply creates /Library/GPUBundles/NVMTLDriver.use-library, because the copy holds the older Mesa; installing this package's copy (from the app's Driver page or with ssv-install.sh --apply) removes it again (0.1.6 and later; with 0.1.5 and earlier run sudo rm /Library/GPUBundles/NVMTLDriver.use-library after ssv-install.sh --apply in Terminal); then restart.

0.1.3'ten olduğu gibi; ayrıca NMXAGDC.kext, video çözücü ve Mesa'nın Vulkan sürücüsü de yeni (firmware'inkinden yüksek tazeleme hızları, varsayılan olarak açık Adaptive-Sync modları, monitörün tam tazeleme hızında isteğe bağlı HiDPI modları, tam aralıklı videonun tam aralıklı çözülmesi, WindowServer'ın derlenmiş shader'larını saklaması). Sistem diski kopyasını kurduysanız install.sh --apply, kopya eski Mesa'yı taşıdığı için /Library/GPUBundles/NVMTLDriver.use-library dosyasını oluşturur; bu paketin kopyasını kurmak (uygulamanın Sürücü sayfasından ya da ssv-install.sh --apply ile) onu yeniden siler (0.1.6 ve sonrası; 0.1.5 ve öncesinde Terminal'de ssv-install.sh --apply'dan sonra sudo rm /Library/GPUBundles/NVMTLDriver.use-library çalıştırın); sonra yeniden başlatın.

From 0.1.0 or 0.1.10.1.0 ya da 0.1.1'den

Every kext, the Metal driver and the video libraries are new, IntelXe.kext in the EFI too (it closes a security hole: an unprivileged process could get writable GPU mappings of pages it may only read). Install the package (the app: Download v0.1.6, then Install this package; or sudo ./install.sh --apply), then replace IntelXe.kext in the EFI before you reboot (the app's EFI page or sudo ./efi.sh --apply on macOS, IntelXe Manager for Windows or IntelXe-EFI.ps1 on Windows, or copy it by hand; its config.plist entry stays as it is).

--apply also installs the boot guard's LaunchDaemon and replaces the allow-list of 0.1.0 and 0.1.1 (with or without the -NotificationCenter line 0.1.1's guide asked for), so that Safari's GPU process, the Dock's icons and the desktop widgets use the driver again. An allow-list you changed in another way is kept: compare it with the package's Library/GPUBundles/nvmtl-allow.txt. If you had installed the system-volume copy, --apply makes every process use the /Library copy until you install this package's, which removes /Library/GPUBundles/NVMTLDriver.use-library again (0.1.6 and later; with 0.1.5 and earlier remove it by hand). Check UEFI > Output > ReconnectGraphicsOnConnect = false in your config.plist (stage 2, item 5), above all before you move OpenCore to a RELEASE build.

Bütün kext'ler, Metal sürücüsü ve video kütüphaneleri yeni, EFI'deki IntelXe.kext de (bir güvenlik açığını kapatıyor: yetkisiz bir süreç yalnızca okuyabileceği sayfalara yazılabilir GPU eşlemesi alabiliyordu). Paketi kurun (uygulamada v0.1.6 sürümünü indir, sonra Bu paketi kur; ya da sudo ./install.sh --apply), sonra yeniden başlatmadan önce EFI'deki IntelXe.kext'i değiştirin (macOS'ta uygulamanın EFI sayfası ya da sudo ./efi.sh --apply, Windows'ta Windows için IntelXe Manager ya da IntelXe-EFI.ps1, ya da elle kopyalayın; config.plist kaydı olduğu gibi kalır).

--apply açılış korumasının LaunchDaemon'ını da kurar ve 0.1.0 ile 0.1.1'in izin listesini (0.1.1 rehberinin istediği -NotificationCenter satırıyla ya da satırsız) değiştirir; böylece Safari'nin GPU süreci, Dock simgeleri ve masaüstü widget'ları yeniden sürücüyü kullanır. Başka bir biçimde değiştirdiğiniz izin listesi korunur: paketteki Library/GPUBundles/nvmtl-allow.txt ile karşılaştırın. Sistem diski kopyasını kurduysanız --apply, bu paketinkini kurana kadar bütün süreçlere /Library kopyasını kullandırır; o kurulum /Library/GPUBundles/NVMTLDriver.use-library dosyasını yeniden siler (0.1.6 ve sonrası; 0.1.5 ve öncesinde elle silin). config.plist'te UEFI > Output > ReconnectGraphicsOnConnect = false olduğunu kontrol edin (2. aşama, 5. madde), özellikle OpenCore'u RELEASE sürümüne geçirmeden önce.

From the private builds named B580 (before 0.1.0)0.1.0'dan önceki, B580 adlı özel derlemelerden

B580.kext is now IntelXe.kext, B580FB.kext is IntelXeFB.kext, and the boot-args start with intelxe_. Do both halves before you reboot:

  • in the EFI, delete EFI/OC/Kexts/B580.kext, copy IntelXe.kext in its place and change its Kernel > Add entry to the paths in stage 4 (only one of the two may be in your EFI);
  • run sudo ./install.sh --apply, which backs up and removes /Library/Extensions/B580FB.kext (--undo puts it back, and then your EFI needs B580.kext again).

With only one of the two, macOS comes up without the driver. If you installed the system-volume copy of the earlier build, --apply creates /Library/GPUBundles/NVMTLDriver.use-library, so that every process uses the /Library copy; install this package's system-volume copy, which removes that file again (0.1.6 and later; with 0.1.5 and earlier run sudo rm /Library/GPUBundles/NVMTLDriver.use-library after it), and reboot.

Rename the boot-args too. 0.1.x still reads the earlier names when the new one is absent and logs boot-arg ... is deprecated once per name; later releases read only the new names. Values and meanings are unchanged. To see which ones you still use:

B580.kext'in adı artık IntelXe.kext, B580FB.kext'inki IntelXeFB.kext; boot-arg'lar da intelxe_ ile başlıyor. Yeniden başlatmadan önce iki yarıyı da yapın:

  • EFI'de EFI/OC/Kexts/B580.kext'i silin, yerine IntelXe.kext'i kopyalayın ve Kernel > Add kaydını 4. aşamadaki yollara çevirin (EFI'nizde ikisinden yalnızca biri olabilir);
  • sudo ./install.sh --apply çalıştırın; /Library/Extensions/B580FB.kext'i yedekleyip kaldırır (--undo onu geri koyar, o zaman EFI'niz yeniden B580.kext ister).

Yalnızca birini yaparsanız macOS sürücüsüz açılır. Eski derlemenin sistem diski kopyasını kurduysanız --apply, her süreç /Library kopyasını kullansın diye /Library/GPUBundles/NVMTLDriver.use-library dosyasını oluşturur; bu paketin sistem diski kopyasını kurun; bu, o dosyayı yeniden siler (0.1.6 ve sonrası; 0.1.5 ve öncesinde ardından sudo rm /Library/GPUBundles/NVMTLDriver.use-library çalıştırın). Sonra yeniden başlatın.
