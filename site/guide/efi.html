Stage 2: SIP, AMFI, quirks and the console setting2. aşama: SIP, AMFI, quirk'ler ve konsol ayarı

In config.plist:

  1. Booter > Quirks > ResizeAppleGpuBars = 10. macOS cannot map the card's 16 GB BAR; this gives it a 1 GB window.
    Why 10, and OpenCore's warning

    OpenCore's ocvalidate reports this value as "unstable with macOS sleep-wake": the card forgets its BAR size in sleep and macOS does not set it again, which Apple's own GPU drivers do not handle. IntelXe.kext sets it again on wake, as Linux does, and sleep works on the test machine. The warning is expected; keep 10. (9 gets the same warning with half the window; 0, the value ocvalidate accepts, works too, but its 256 MB window is too small for the desktop and a game. Details: docs/design/DESIGN-rebar-window.md in the source repository.)

  2. Kernel > Quirks > DisableIoMapper = true.
  3. NVRAM > Add > 7C436110-AB2A-4BBB-A880-FE41995C9F82:
    • csr-active-config = 03080000 (Data): SIP relaxed, so that unsigned kexts load from the Auxiliary Kernel Collection;
    • boot-args: add amfi_get_out_of_my_way=0x1 (otherwise WindowServer refuses the unsigned Metal driver) and intelxe_surfvram=2 (IOSurfaces shared in VRAM between processes).
  4. NVRAM > Delete > 7C436110-AB2A-4BBB-A880-FE41995C9F82 must list csr-active-config and boot-args (Dortania's sample config does), so that the new values replace the old ones.
  5. UEFI > Output > ReconnectGraphicsOnConnect = false.
    Why?

    With true, OpenCore's RELEASE build sets up the console before the card's firmware display (GOP) is back from the reconnect; macOS then boots without a console framebuffer, Lilu never completes its start, VirtualSMC's SMC device is not hooked up, and watchdogd panics the boot about 20 seconds in. OpenCore's DEBUG build is slow enough to hide this.

  6. For the system-volume copy (Safari on the GPU, Optional extras): Misc > Security > SecureBootModel = Disabled.

Reboot into macOS. The screen still runs on the firmware output. Then install the driver (From macOS), and come back for stage 4 before the next reboot.

config.plist'te:

  1. Booter > Quirks > ResizeAppleGpuBars = 10. macOS, kartın 16 GB'lık BAR'ını eşleyemiyor; bu ayar 1 GB'lık bir pencere açıyor.
    Neden 10; OpenCore'un uyarısı

    OpenCore'un ocvalidate aracı bu değer için "unstable with macOS sleep-wake" uyarısı veriyor: kart uykuda BAR boyutunu unutuyor ve macOS onu yeniden ayarlamıyor; Apple'ın kendi GPU sürücüleri bununla başa çıkamıyor. IntelXe.kext uyanışta boyutu Linux'taki gibi yeniden ayarlıyor ve test makinesinde uyku çalışıyor. Bu uyarı beklenen bir şey; 10'da bırakın. (9 aynı uyarıyı yarım pencereyle alıyor; ocvalidate'in kabul ettiği 0 da çalışıyor, ama 256 MB'lık penceresi masaüstü ve bir oyun için küçük kalıyor. Ayrıntılar: kaynak deposunda docs/design/DESIGN-rebar-window.md.)

  2. Kernel > Quirks > DisableIoMapper = true.
  3. NVRAM > Add > 7C436110-AB2A-4BBB-A880-FE41995C9F82 altında:
    • csr-active-config = 03080000 (Data): imzasız kext'ler Yardımcı Kernel Koleksiyonu'ndan yüklenebilsin diye SIP gevşetiliyor;
    • boot-args'a amfi_get_out_of_my_way=0x1 (yoksa WindowServer imzasız Metal sürücüsünü reddediyor) ve intelxe_surfvram=2 (süreçler arasında VRAM'de paylaşılan IOSurface'ler) ekleyin.
  4. NVRAM > Delete > 7C436110-AB2A-4BBB-A880-FE41995C9F82 listesinde csr-active-config ve boot-args olmalı (Dortania'nın örnek yapılandırmasında var); yeni değerler eskilerin yerine böyle geçiyor.
  5. UEFI > Output > ReconnectGraphicsOnConnect = false.
    Neden?

    Bu ayar true olursa OpenCore'un RELEASE sürümü, kartın UEFI ekran sürücüsü (GOP) yeniden bağlanmadan konsolu kurmaya çalışıyor. macOS konsol ekranı olmadan açılıyor, Lilu başlatmasını tamamlayamıyor, VirtualSMC'nin SMC aygıtı bağlanmıyor ve watchdogd açılışın yaklaşık 20. saniyesinde panik veriyor. OpenCore'un DEBUG sürümü yavaş olduğu için bu sorunu gizliyor.

  6. Sistem diski kopyası için (GPU'da Safari, İsteğe bağlı ekler): Misc > Security > SecureBootModel = Disabled.

macOS'u yeniden başlatın. Ekran hâlâ UEFI çıktısında çalışır. Sonra sürücüyü kurun (macOS'tan) ve bir sonraki yeniden başlatmadan önce 4. aşama için buraya dönün.

Stage 4: IntelXe.kext4. aşama: IntelXe.kext

After the driver is installed, before the next macOS boot. Take the files from intel-gpu-macos-driver-0.1.6-efi.zip (the macOS package has the same files under EFI/OC/). Mount the EFI partition as above; on the PC itself, sudo diskutil mount disk0s1 with your partition.

Copy IntelXe.kext to EFI/OC/Kexts/ and add it under Kernel > Add: BundlePath IntelXe.kext, ExecutablePath Contents/MacOS/IntelXe, PlistPath Contents/Info.plist, Enabled true. This is the GPU driver (GuC/HuC firmware included); it does not need Lilu.

Sürücü kurulduktan sonra, macOS bir daha açılmadan önce. Dosyaları intel-gpu-macos-driver-0.1.6-efi.zip'ten alın (macOS paketinde de EFI/OC/ altında aynıları var). EFI bölümünü yukarıdaki gibi bağlayın; kurulacak bilgisayarda kendi bölümünüzle sudo diskutil mount disk0s1.

IntelXe.kext'i EFI/OC/Kexts/ klasörüne kopyalayın ve Kernel > Add altına ekleyin: BundlePath IntelXe.kext, ExecutablePath Contents/MacOS/IntelXe, PlistPath Contents/Info.plist, Enabled true. GPU sürücüsü bu (GuC/HuC yazılımları içinde); Lilu istemiyor.

Stage 4: SSDT-ARCOFF and your card's ACPI path4. aşama: SSDT-ARCOFF ve kartınızın ACPI yolu

SSDT-ARCOFF.aml hides the card from macOS's generic display driver (on Tahoe that driver otherwise takes the card and the IntelXe kexts cannot start). Its ACPI path depends on the board. The shipped table is for a board whose ACPI names the slot's root port \_SB.PC00.PEG1 and the card's own PCIe switch below it PEGP. Below PEGP every B580 looks the same: a downstream port at PCI(0100), then the GPU at PCI(0000). Find your path:

SSDT-ARCOFF.aml, kartı macOS'un genel ekran sürücüsünden gizliyor (Tahoe'da o sürücü kartı alırsa IntelXe kext'leri başlayamıyor). ACPI yolu anakarta göre değişiyor. Paketteki tablo, yuvanın kök portunu \_SB.PC00.PEG1, kartın kendi PCIe anahtarını da onun altında PEGP diye adlandıran bir anakart için. PEGP'nin altı her B580'de aynı: PCI(0100)'de bir alt port, PCI(0000)'da GPU. Kendi yolunuzu şöyle bulun:

SystemSistemHowNasıl
WindowsDevice Manager → Display adapters → the Arc card (or "Microsoft Basic Display Adapter" without Intel's driver) → Properties → Details → Location paths. The ACPI(...) line looks like ACPI(_SB_)#ACPI(PC00)#ACPI(PEG1)#ACPI(PEGP)#PCI(0100)#PCI(0000), which is \_SB.PC00.PEG1.PEGPAygıt Yöneticisi → Görüntü bağdaştırıcıları → Arc kartı (Intel'in sürücüsü yoksa "Microsoft Temel Görüntü Bağdaştırıcısı") → Özellikler → Ayrıntılar → Konum yolları. ACPI(...) ile başlayan satır ACPI(_SB_)#ACPI(PC00)#ACPI(PEG1)#ACPI(PEGP)#PCI(0100)#PCI(0000) gibi görünür; bu \_SB.PC00.PEG1.PEGP demektir
Linuxlspci -nn | grep -e e20b -e e20c -e e211 -e e212 gives the GPU (e.g. 03:00.0); lspci -tv shows the card's upstream port two levels above it (e.g. 01:00.0); cat /sys/bus/pci/devices/0000:01:00.0/firmware_node/path prints its ACPI path, e.g. \_SB_.PC00.PEG1.PEGPlspci -nn | grep -e e20b -e e20c -e e211 -e e212 GPU'yu verir (ör. 03:00.0); lspci -tv kartın iki seviye üstündeki portu gösterir (ör. 01:00.0); cat /sys/bus/pci/devices/0000:01:00.0/firmware_node/path ACPI yolunu yazar, ör. \_SB_.PC00.PEG1.PEGP
macOSgfxutil lists every PCI device with its ACPI path: take the 8086:e20b line (8086:e20c on a B570, 8086:e211 on a Pro B60, 8086:e212 on a Pro B50). IORegistryExplorer shows the same names in the IOService plane (PC00@0 → PEG1@1 → PEGP@0 → ...)gfxutil bütün PCI aygıtlarını ACPI yollarıyla listeler: 8086:e20b satırına bakın (B570'te 8086:e20c, Pro B60'ta 8086:e211, Pro B50'de 8086:e212). IORegistryExplorer aynı adları IOService düzleminde gösterir (PC00@0 → PEG1@1 → PEGP@0 → ...)

If your path is the shipped one (\_SB.PC00.PEG1.PEGP), use SSDT-ARCOFF.aml as it is. Otherwise, on macOS, let efi.sh or the app's EFI page adapt it (From macOS); it does this for a path of any length, and so does IntelXe-EFI.ps1 on Windows. By hand, put your path in the two places of SSDT-ARCOFF.dsl that name it (the External line and the Scope line) and compile it with iasl SSDT-ARCOFF.dsl. iasl is part of ACPICA: on Windows ACPICA's Windows binary tools (acpica.org, Downloads), on Linux the acpica-tools (or iasl) package, on macOS brew install acpica or the iasl inside MaciASL.

If no ACPI(...) part names the card's upstream port (the last ACPI(...) part is followed by three PCI(...) parts instead of two), the table needs one more bridge level: open an issue with your Location paths line.

Copy the .aml to EFI/OC/ACPI/ and add it under ACPI > Add (Path SSDT-ARCOFF.aml, Enabled true).

Yolunuz paketteki gibiyse (\_SB.PC00.PEG1.PEGP) SSDT-ARCOFF.aml'yi olduğu gibi kullanın. Değilse macOS'ta tabloyu efi.sh ya da uygulamanın EFI sayfası uyarlasın (macOS'tan); yolun uzunluğu ne olursa olsun bunu yapar, Windows'ta IntelXe-EFI.ps1 de yapar. Elle yapmak için SSDT-ARCOFF.dsl'de yolun geçtiği iki yere (External ve Scope satırları) kendi yolunuzu yazıp iasl SSDT-ARCOFF.dsl ile derleyin. iasl, ACPICA'nın parçası: Windows'ta ACPICA'nın Windows araçları (acpica.org, Downloads), Linux'ta acpica-tools (ya da iasl) paketi, macOS'ta brew install acpica ya da MaciASL'in içindeki iasl.

Hiçbir ACPI(...) parçası kartın üst portunu adlandırmıyorsa (son ACPI(...) parçasından sonra iki değil üç PCI(...) geliyorsa) tabloya bir köprü seviyesi daha gerekiyor: Konum yolları satırınızla bir issue açın.

.aml dosyasını EFI/OC/ACPI/ klasörüne kopyalayın ve ACPI > Add altına ekleyin (Path SSDT-ARCOFF.aml, Enabled true).

On a hybrid Intel CPU, add HybridPM next (below); otherwise reboot and check.

Hibrit bir Intel işlemcide sırada HybridPM var (aşağıda); yoksa yeniden başlatın ve kontrol edin.

Hybrid Intel CPUs (12th-14th gen): HybridPM.kextHibrit Intel işlemciler (12.-14. nesil): HybridPM.kext

macOS's CPU power management (XCPM) predates CPUs with performance and efficiency cores. On Alder Lake and Raptor Lake it caps the P-cores (an i7-14700K stayed at 4.4 GHz instead of 5.6) and can hold fully busy cores at 800 MHz. The GPU driver does a lot of CPU work per command buffer, so the GPU looks slow too: on the test machine Geekbench's GPU scores were about a third higher with HybridPM.kext, and one CPU thread more than twice as fast. HybridPM is separate from the GPU driver and optional; it is in the -efi.zip and in the macOS package under EFI/OC/Kexts/.

Which CPUs: 12th, 13th and 14th generation Core i3/i5/i7/i9 with P- and E-cores (Alder Lake and Raptor Lake, desktop and laptop; e.g. i5-12600K, i5-13400F, i7-14700K, i7-13620H). Not Core Ultra: it leaves those alone, as it does CPUs without E-cores and older CPUs (it only logs why). The model list is in kernel/HybridPM/README.md in the repository.

Adding it: on the PC, stage 4 does it: efi.sh --plan / sudo ./efi.sh --apply and the app's EFI page copy HybridPM.kext with IntelXe.kext when the CPU's name is one of these, and add its entry right below Lilu.kext's (an existing entry is turned on; an earlier build under the same name is replaced). They leave it out, with a note, when the EFI does not load Lilu. IntelXe-EFI.ps1 on Windows does the same, by the CPU of the PC it runs on (not yet run on Windows). By hand:

  1. It is a Lilu plugin. Most OpenCore EFIs already have Lilu.kext for VirtualSMC; if yours has not, add it from acidanthera/Lilu (1.7.2 on the test machine). This package does not include Lilu.
  2. Copy HybridPM.kext to EFI/OC/Kexts/ and add it under Kernel > Add, below Lilu.kext: BundlePath HybridPM.kext, ExecutablePath Contents/MacOS/HybridPM, PlistPath Contents/Info.plist, Enabled true.
  3. Reboot. It starts working 20 seconds after boot.

macOS'un işlemci güç yönetimi (XCPM), performans ve verimlilik çekirdekli işlemcilerden eski. Alder Lake ve Raptor Lake'te P çekirdeklerini sınırlıyor (bir i7-14700K 5,6 yerine 4,4 GHz'de kaldı) ve tam yüklü çekirdekleri 800 MHz'de tutabiliyor. GPU sürücüsü her komut arabelleği için işlemcide epey iş yapıyor, bu yüzden GPU da yavaş görünüyor: test makinesinde Geekbench'in GPU puanları HybridPM.kext ile yaklaşık üçte bir yüksekti, tek işlemci iş parçacığı iki kattan fazla hızlıydı. HybridPM GPU sürücüsünden ayrı ve isteğe bağlı; -efi.zip'te ve macOS paketinde EFI/OC/Kexts/ altında.

Hangi işlemciler: P ve E çekirdekli 12., 13. ve 14. nesil Core i3/i5/i7/i9 (Alder Lake ve Raptor Lake, masaüstü ve dizüstü; örneğin i5-12600K, i5-13400F, i7-14700K, i7-13620H). Core Ultra değil: onlara dokunmuyor; E çekirdeği olmayan ve daha eski işlemcilere de dokunmuyor (yalnızca nedenini günlüğe yazıyor). Model listesi depodaki kernel/HybridPM/README.md'de.

Eklemek: kurulacak bilgisayarda 4. aşama bunu yapıyor: efi.sh --plan / sudo ./efi.sh --apply ve uygulamanın EFI sayfası, işlemcinin adı bunlardan biriyse HybridPM.kext'i IntelXe.kext ile birlikte kopyalıyor ve kaydını Lilu.kext'in kaydının hemen altına ekliyor (var olan kayıt açılıyor; aynı adlı eski bir derleme değiştiriliyor). EFI Lilu yüklemiyorsa bir notla dışarıda bırakıyor. Windows'taki IntelXe-EFI.ps1 de, çalıştığı bilgisayarın işlemcisine bakarak aynısını yapıyor (henüz Windows'ta çalışmadı). Elle:

  1. Bir Lilu eklentisi. Çoğu OpenCore EFI'sinde VirtualSMC için Lilu.kext zaten var; sizinkinde yoksa acidanthera/Lilu'dan ekleyin (test makinesinde 1.7.2). Bu paket Lilu içermiyor.
  2. HybridPM.kext'i EFI/OC/Kexts/ klasörüne kopyalayın ve Kernel > Add altına Lilu.kext'in altına ekleyin: BundlePath HybridPM.kext, ExecutablePath Contents/MacOS/HybridPM, PlistPath Contents/Info.plist, Enabled true.
  3. Yeniden başlatın. Açılıştan 20 saniye sonra devreye giriyor.

Checking itKontrol etmek

sysctl debug.hybridpm.enabled debug.hybridpm.why debug.hybridpm.route

Expected outputBeklenen çıktı

debug.hybridpm.enabled: 1, debug.hybridpm.why: on (model 0xB7), debug.hybridpm.route: 1
./hpmstat 1000 3     # in the package folder: each core's clock and load, HWP limits, package power
./hpmstat 1000 3     # paket klasöründe: her çekirdeğin saati ve yükü, HWP sınırları, paket gücü

With enabled 0, why says why: not hybrid or unsupported model (Core Ultra and others), or route 3 when a macOS update changed the routine it corrects; macOS then runs as without it. When debug.hybridpm does not exist, HybridPM or Lilu did not load (kmutil showloaded | grep -i -e lilu -e hybridpm).

Turning it off: add -hpmoff to the boot-args, or set its Kernel > Add entry to Enabled false. Until the next restart, sudo sysctl debug.hybridpm.hwp=0 debug.hybridpm.autonomous=0 debug.hybridpm.epp=-1 debug.hybridpm.eet_off=0 gives back macOS's own settings.

enabled 0 ise why nedenini söyler: not hybrid ya da unsupported model (Core Ultra ve diğerleri), ya da bir macOS güncellemesi düzelttiği rutini değiştirdiyse route 3; macOS o zaman onsuzmuş gibi çalışır. debug.hybridpm hiç yoksa HybridPM ya da Lilu yüklenmemiştir (kmutil showloaded | grep -i -e lilu -e hybridpm).

Kapatmak: boot-args'a -hpmoff ekleyin ya da Kernel > Add kaydını Enabled false yapın. Bir sonraki yeniden başlatmaya kadar sudo sysctl debug.hybridpm.hwp=0 debug.hybridpm.autonomous=0 debug.hybridpm.epp=-1 debug.hybridpm.eet_off=0 macOS'un kendi ayarlarını geri verir.

Then reboot and check the driver.
