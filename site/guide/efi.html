4. IntelXe.kext and SSDT-ARCOFF (the EFI)

Take the files from intel-gpu-macos-driver-0.1.4-efi.zip (the macOS package has the same files under EFI/OC/). Mount the EFI partition as in stage 2; on the PC itself, sudo diskutil mount disk0s1 with your partition.

On the PC itself, efi.sh in the macOS package does steps 1 to 3 (and stage 2's settings) for you: it finds the EFI OpenCore booted from, backs up the whole EFI folder, copies the files and enables their config.plist entries. It reads your card's ACPI path (step 2) from the I/O Registry; when it is not the shipped table's, it writes your path into a copy of SSDT-ARCOFF.aml and adds that (the plan says "adapted to this card's port"), so there is no table to edit or compile. On a 12th-14th gen hybrid Intel CPU it adds HybridPM.kext as well (below). ./efi.sh --plan shows the changes, sudo ./efi.sh --apply makes them, sudo ./efi.sh --undo takes them back; --settings-plan / --settings-apply do stage 2. ./efi.sh alone lists every option. The IntelXe Manager app has the same on its EFI page.

On Windows, IntelXe-EFI.ps1 in the -efi.zip does steps 1 and 3 (Driver: plan, Driver: apply) in the EFI folder you choose, with a backup and an undo. Windows cannot check the ACPI path the way efi.sh does on macOS, so it adds SSDT-ARCOFF.aml only when you tick its box and give your card's path from step 2 (it reads it from Device Manager when Windows runs on the PC with the card); for a path other than the shipped table's it adapts a copy of the table, as efi.sh does. On a 12th-14th gen hybrid Intel CPU it adds HybridPM.kext too, by the CPU of the PC it runs on: run it on the PC that boots the EFI. These two steps are checked on macOS against efi.sh but have not run on Windows yet. See README-Windows.md in the zip.

  1. Copy IntelXe.kext to EFI/OC/Kexts/ and add it under Kernel > Add: BundlePath IntelXe.kext, ExecutablePath Contents/MacOS/IntelXe, PlistPath Contents/Info.plist, Enabled true. This is the GPU driver (GuC/HuC firmware included); it does not need Lilu.
  2. SSDT-ARCOFF.aml hides the card from macOS's generic display driver (on Tahoe that driver otherwise takes the card and the IntelXe kexts cannot start). Its ACPI path depends on the board. The shipped table is for a board whose ACPI names the slot's root port \_SB.PC00.PEG1 and the card's own PCIe switch below it PEGP. Below PEGP every B580 looks the same: a downstream port at PCI(0100), then the GPU at PCI(0000). Find your path:
    SystemHow
    WindowsDevice Manager → Display adapters → the Arc card (or "Microsoft Basic Display Adapter" without Intel's driver) → Properties → Details → Location paths. The ACPI(...) line looks like ACPI(_SB_)#ACPI(PC00)#ACPI(PEG1)#ACPI(PEGP)#PCI(0100)#PCI(0000), which is \_SB.PC00.PEG1.PEGP
    Linux`lspci -nn \grep -e e20b -e e20c gives the GPU (e.g. 03:00.0); lspci -tv shows the card's upstream port two levels above it (e.g. 01:00.0); cat /sys/bus/pci/devices/0000:01:00.0/firmware_node/path prints its ACPI path, e.g. \_SB_.PC00.PEG1.PEGP`
    macOSgfxutil lists every PCI device with its ACPI path: take the 8086:e20b line (8086:e20c on a B570). IORegistryExplorer shows the same names in the IOService plane (PC00@0 → PEG1@1 → PEGP@0 → ...)

    If your path is the shipped one (\_SB.PC00.PEG1.PEGP), use SSDT-ARCOFF.aml as it is. Otherwise, on macOS, let efi.sh or the app's EFI page adapt it (above); it does this for a path of any length. By hand, put your path in the two places of SSDT-ARCOFF.dsl that name it (the External line and the Scope line) and compile it with iasl SSDT-ARCOFF.dsl. iasl is part of ACPICA: on Windows ACPICA's Windows binary tools (acpica.org, Downloads), on Linux the acpica-tools (or iasl) package, on macOS brew install acpica or the iasl inside MaciASL. If no ACPI(...) part names the card's upstream port (the last ACPI(...) part is followed by three PCI(...) parts instead of two), the table needs one more bridge level: open an issue with your Location paths line.

  3. Copy the .aml to EFI/OC/ACPI/ and add it under ACPI > Add (Path SSDT-ARCOFF.aml, Enabled true).
  4. Reboot. The desktop should now be accelerated: transparency and blur, smooth window dragging, and About This Mac names the card (the Arc B580 with 12 GB). In Terminal, kmutil showloaded | grep -i intelxe lists IntelXe and IntelXeFB, and sysctl debug.nmxaccelfb prints 1.

Hybrid Intel CPUs (12th-14th gen): HybridPM.kext

macOS's CPU power management (XCPM) predates CPUs with performance and efficiency cores. On Alder Lake and Raptor Lake it caps the P-cores (an i7-14700K stayed at 4.4 GHz instead of 5.6) and can hold fully busy cores at 800 MHz. The GPU driver does a lot of CPU work per command buffer, so the GPU looks slow too: on the test machine Geekbench's GPU scores were about a third higher with HybridPM.kext, and one CPU thread more than twice as fast. HybridPM is separate from the GPU driver and optional; it is in the -efi.zip and in the macOS package under EFI/OC/Kexts/.

Which CPUs: 12th, 13th and 14th generation Core i3/i5/i7/i9 with P- and E-cores (Alder Lake and Raptor Lake, desktop and laptop; e.g. i5-12600K, i5-13400F, i7-14700K, i7-13620H). Not Core Ultra: it leaves those alone, as it does CPUs without E-cores and older CPUs (it only logs why). The model list is in kernel/HybridPM/README.md in the repository.

Adding it: on the PC, stage 4 does it: efi.sh --plan / sudo ./efi.sh --apply and the app's EFI page copy HybridPM.kext with IntelXe.kext when the CPU's name is one of these, and add its entry right below Lilu.kext's (an existing entry is turned on; an earlier build under the same name is replaced). They leave it out, with a note, when the EFI does not load Lilu. IntelXe-EFI.ps1 on Windows does the same, by the CPU of the PC it runs on (not yet run on Windows). By hand:

  1. It is a Lilu plugin. Most OpenCore EFIs already have Lilu.kext for VirtualSMC; if yours has not, add it from acidanthera/Lilu (1.7.2 on the test machine). This package does not include Lilu.
  2. Copy HybridPM.kext to EFI/OC/Kexts/ and add it under Kernel > Add, below Lilu.kext: BundlePath HybridPM.kext, ExecutablePath Contents/MacOS/HybridPM, PlistPath Contents/Info.plist, Enabled true.
  3. Reboot. It starts working 20 seconds after boot.

Checking it:

sysctl debug.hybridpm.enabled debug.hybridpm.why debug.hybridpm.route
# debug.hybridpm.enabled: 1, debug.hybridpm.why: on (model 0xB7), debug.hybridpm.route: 1
./hpmstat 1000 3     # in the package folder: each core's clock and load, HWP limits, package power

With enabled 0, why says why: not hybrid or unsupported model (Core Ultra and others), or route 3 when a macOS update changed the routine it corrects; macOS then runs as without it. When debug.hybridpm does not exist, HybridPM or Lilu did not load (kmutil showloaded | grep -i -e lilu -e hybridpm).

Turning it off: add -hpmoff to the boot-args, or set its Kernel > Add entry to Enabled false. Until the next restart, sudo sysctl debug.hybridpm.hwp=0 debug.hybridpm.autonomous=0 debug.hybridpm.epp=-1 debug.hybridpm.eet_off=0 gives back macOS's own settings.

4. IntelXe.kext ve SSDT-ARCOFF (EFI)

Dosyaları intel-gpu-macos-driver-0.1.4-efi.zip'ten alın (macOS paketinde de EFI/OC/ altında aynıları var). EFI bölümünü

  1. aşamadaki gibi bağlayın; kurulacak bilgisayarda kendi bölümünüzle sudo diskutil mount disk0s1.

Kurulacak bilgisayarın kendisinde, macOS paketindeki efi.sh 1-3. maddeleri (ve 2. aşamanın ayarlarını) sizin yerinize yapar: OpenCore'un açıldığı EFI'yi bulur, EFI klasörünün tamamını yedekler, dosyaları kopyalar, config.plist kayıtlarını açar. Kartınızın ACPI yolunu (2. madde) I/O Registry'den okur; yol paketteki tablonunkinden farklıysa SSDT-ARCOFF.aml'ın bir kopyasına sizin yolunuzu yazıp onu ekler (plan bunu "adapted to this card's port" diye belirtir); düzenlenecek ya da derlenecek bir tablo kalmaz. 12.-14. nesil hibrit bir Intel işlemcide HybridPM.kext'i de ekler (aşağıda, "Hibrit Intel işlemciler"). ./efi.sh --plan değişiklikleri gösterir, sudo ./efi.sh --apply yapar, sudo ./efi.sh --undo geri alır; --settings-plan / --settings-apply 2. aşamayı yapar. Bütün seçenekler için yalnızca ./efi.sh. IntelXe Manager uygulamasının EFI sayfası da aynısını yapar.

Windows'ta -efi.zip'teki IntelXe-EFI.ps1 1. ve 3. maddeleri (Driver: plan, Driver: apply) seçtiğiniz EFI klasöründe, yedek ve geri alma ile yapar. Windows, ACPI yolunu efi.sh'in macOS'ta yaptığı gibi denetleyemez; bu yüzden SSDT-ARCOFF.aml'ı yalnızca kutusunu işaretleyip 2. maddedeki kart yolunuzu yazdığınızda ekler (Windows kartın takılı olduğu bilgisayarda çalışıyorsa yolu Aygıt Yöneticisi'nden okur); paketteki tablonunkinden farklı bir yolda, efi.sh gibi tablonun bir kopyasını uyarlar. 12.-14. nesil hibrit bir Intel işlemcide HybridPM.kext'i de ekler; çalıştığı bilgisayarın işlemcisine bakar, bu yüzden onu EFI'yi açacak bilgisayarda çalıştırın. Bu iki adım macOS'ta efi.sh'e karşı denendi ama henüz Windows'ta çalışmadı. Zip'teki README-Windows.md'ye bakın.

  1. IntelXe.kext'i EFI/OC/Kexts/ klasörüne kopyalayın ve Kernel > Add altına ekleyin: BundlePath IntelXe.kext, ExecutablePath Contents/MacOS/IntelXe, PlistPath Contents/Info.plist, Enabled true. GPU sürücüsü bu (GuC/HuC yazılımları içinde); Lilu istemiyor.
  2. SSDT-ARCOFF.aml, kartı macOS'un genel ekran sürücüsünden gizliyor (Tahoe'da o sürücü kartı alırsa IntelXe kext'leri başlayamıyor). ACPI yolu anakarta göre değişiyor. Paketteki tablo, yuvanın kök portunu \_SB.PC00.PEG1, kartın kendi PCIe anahtarını da onun altında PEGP diye adlandıran bir anakart için. PEGP'nin altı her B580'de aynı: PCI(0100)'de bir alt port, PCI(0000)'da GPU. Kendi yolunuzu şöyle bulun:
    SistemNasıl
    WindowsAygıt Yöneticisi → Görüntü bağdaştırıcıları → Arc kartı (Intel'in sürücüsü yoksa "Microsoft Temel Görüntü Bağdaştırıcısı") → Özellikler → Ayrıntılar → Konum yolları. ACPI(...) ile başlayan satır ACPI(_SB_)#ACPI(PC00)#ACPI(PEG1)#ACPI(PEGP)#PCI(0100)#PCI(0000) gibi görünür; bu \_SB.PC00.PEG1.PEGP demektir
    Linux`lspci -nn \grep -e e20b -e e20c GPU'yu verir (ör. 03:00.0); lspci -tv kartın iki seviye üstündeki portu gösterir (ör. 01:00.0); cat /sys/bus/pci/devices/0000:01:00.0/firmware_node/path ACPI yolunu yazar, ör. \_SB_.PC00.PEG1.PEGP`
    macOSgfxutil bütün PCI aygıtlarını ACPI yollarıyla listeler: 8086:e20b satırına bakın (B570'te 8086:e20c). IORegistryExplorer aynı adları IOService düzleminde gösterir (PC00@0 → PEG1@1 → PEGP@0 → ...)

    Yolunuz paketteki gibiyse (\_SB.PC00.PEG1.PEGP) SSDT-ARCOFF.aml'yi olduğu gibi kullanın. Değilse macOS'ta tabloyu efi.sh ya da uygulamanın EFI sayfası uyarlasın (yukarıda); yolun uzunluğu ne olursa olsun bunu yapar. Elle yapmak için SSDT-ARCOFF.dsl'de yolun geçtiği iki yere (External ve Scope satırları) kendi yolunuzu yazıp iasl SSDT-ARCOFF.dsl ile derleyin. iasl, ACPICA'nın parçası: Windows'ta ACPICA'nın Windows araçları (acpica.org, Downloads), Linux'ta acpica-tools (ya da iasl) paketi, macOS'ta brew install acpica ya da MaciASL'in içindeki iasl. Hiçbir ACPI(...) parçası kartın üst portunu adlandırmıyorsa (son ACPI(...) parçasından sonra iki değil üç PCI(...) geliyorsa) tabloya bir köprü seviyesi daha gerekiyor: Konum yolları satırınızla bir issue açın.

  3. .aml dosyasını EFI/OC/ACPI/ klasörüne kopyalayın ve ACPI > Add altına ekleyin (Path SSDT-ARCOFF.aml, Enabled true).
  4. Yeniden başlatın. Masaüstü artık hızlandırmalı olmalı: saydamlık ve bulanıklık, akıcı pencere sürükleme, Bu Mac Hakkında'da kartın adı görünür (12 GB'lık Arc B580). Terminal'de kmutil showloaded | grep -i intelxe IntelXe ve IntelXeFB'yi listeler, sysctl debug.nmxaccelfb de 1 yazar.

Hibrit Intel işlemciler (12.-14. nesil): HybridPM.kext

macOS'un işlemci güç yönetimi (XCPM), performans ve verimlilik çekirdekli işlemcilerden eski. Alder Lake ve Raptor Lake'te P çekirdeklerini sınırlıyor (bir i7-14700K 5,6 yerine 4,4 GHz'de kaldı) ve tam yüklü çekirdekleri 800 MHz'de tutabiliyor. GPU sürücüsü her komut arabelleği için işlemcide epey iş yapıyor, bu yüzden GPU da yavaş görünüyor: test makinesinde Geekbench'in GPU puanları HybridPM.kext ile yaklaşık üçte bir yüksekti, tek işlemci iş parçacığı iki kattan fazla hızlıydı. HybridPM GPU sürücüsünden ayrı ve isteğe bağlı; -efi.zip'te ve macOS paketinde EFI/OC/Kexts/ altında.

Hangi işlemciler: P ve E çekirdekli 12., 13. ve 14. nesil Core i3/i5/i7/i9 (Alder Lake ve Raptor Lake, masaüstü ve dizüstü; örneğin i5-12600K, i5-13400F, i7-14700K, i7-13620H). Core Ultra değil: onlara dokunmuyor; E çekirdeği olmayan ve daha eski işlemcilere de dokunmuyor (yalnızca nedenini günlüğe yazıyor). Model listesi depodaki kernel/HybridPM/README.md'de.

Eklemek: kurulacak bilgisayarda 4. aşama bunu yapıyor: efi.sh --plan / sudo ./efi.sh --apply ve uygulamanın EFI sayfası, işlemcinin adı bunlardan biriyse HybridPM.kext'i IntelXe.kext ile birlikte kopyalıyor ve kaydını Lilu.kext'in kaydının hemen altına ekliyor (var olan kayıt açılıyor; aynı adlı eski bir derleme değiştiriliyor). EFI Lilu yüklemiyorsa bir notla dışarıda bırakıyor. Windows'taki IntelXe-EFI.ps1 de, çalıştığı bilgisayarın işlemcisine bakarak aynısını yapıyor (henüz Windows'ta çalışmadı). Elle:

  1. Bir Lilu eklentisi. Çoğu OpenCore EFI'sinde VirtualSMC için Lilu.kext zaten var; sizinkinde yoksa acidanthera/Lilu'dan ekleyin (test makinesinde 1.7.2). Bu paket Lilu içermiyor.
  2. HybridPM.kext'i EFI/OC/Kexts/ klasörüne kopyalayın ve Kernel > Add altına Lilu.kext'in altına ekleyin: BundlePath HybridPM.kext, ExecutablePath Contents/MacOS/HybridPM, PlistPath Contents/Info.plist, Enabled true.
  3. Yeniden başlatın. Açılıştan 20 saniye sonra devreye giriyor.

Kontrol etmek:

sysctl debug.hybridpm.enabled debug.hybridpm.why debug.hybridpm.route
# debug.hybridpm.enabled: 1, debug.hybridpm.why: on (model 0xB7), debug.hybridpm.route: 1
./hpmstat 1000 3     # paket klasöründe: her çekirdeğin saati ve yükü, HWP sınırları, paket gücü

enabled 0 ise why nedenini söyler: not hybrid ya da unsupported model (Core Ultra ve diğerleri), ya da bir macOS güncellemesi düzelttiği rutini değiştirdiyse route 3; macOS o zaman onsuzmuş gibi çalışır. debug.hybridpm hiç yoksa HybridPM ya da Lilu yüklenmemiştir (kmutil showloaded | grep -i -e lilu -e hybridpm).

Kapatmak: boot-args'a -hpmoff ekleyin ya da Kernel > Add kaydını Enabled false yapın. Bir sonraki yeniden başlatmaya kadar sudo sysctl debug.hybridpm.hwp=0 debug.hybridpm.autonomous=0 debug.hybridpm.epp=-1 debug.hybridpm.eet_off=0 macOS'un kendi ayarlarını geri verir.
