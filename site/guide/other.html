The install refuses: SIP or AMFI not relaxedKurulum çalışmıyor: SIP ya da AMFI gevşetilmemiş

You seeGördüğünüzThe install refuses to run: SIP or AMFI is not relaxed.Kurulum çalışmayı reddediyor: SIP ya da AMFI gevşetilmemiş.

Check firstÖnce bakın

  • ./install.sh alone checks this and changes nothing. The app's Overview shows the same.
  • ./install.sh seçeneksiz çalıştırıldığında yalnızca bunu denetler, hiçbir şeyi değiştirmez. Uygulamanın Genel bakış sayfası da aynı bilgiyi gösterir.

The fixÇözüm

  1. Set csr-active-config and amfi_get_out_of_my_way=0x1 (stage 2).
  2. Put both csr-active-config and boot-args in NVRAM > Delete. Then the new values replace the old ones.
  3. Restart after changing them.
Why?

Stage 2 is not in effect.

  1. csr-active-config ve amfi_get_out_of_my_way=0x1 ayarlarını yapın (2. aşama).
  2. Hem csr-active-config'i hem de boot-args'ı NVRAM > Delete listesine ekleyin. Böylece yeni değerler eskilerin yerine geçer.
  3. Değiştirdikten sonra yeniden başlatın.
Neden?

2. aşama devrede değil.

The app's EFI page finds no EFIUygulamanın EFI sayfası EFI bulamıyor

You seeGördüğünüzThe app's EFI page does not know which EFI OpenCore booted from.Uygulamanın EFI sayfası OpenCore'un hangi EFI'den açıldığını bilmiyor.

The fixÇözüm

  • Choose the EFI partition from the app's list. It shows each with its disk's name and size.
  • Or pick a folder with Use an EFI folder…, for example a USB stick's.
Why does OpenCore not record it?

OpenCore did not record which EFI it booted from. It records it only when Misc > Security > ExposeSensitiveData includes 1. The stage-4 change also adds 1 to ExposeSensitiveData, so that the next boots record it.

Disk numbers are never used: they change between boots.

  • EFI bölümünü uygulamanın listesinden seçin. Liste her bölümü disk adı ve boyutuyla gösterir.
  • Ya da Bir EFI klasörü kullan… ile bir klasör seçin, örneğin bir USB belleğin EFI klasörünü.
OpenCore bunu neden kaydetmemiş?

OpenCore hangi EFI'den açıldığını kaydetmemiş. Bunu yalnızca Misc > Security > ExposeSensitiveData değeri 1'i içeriyorsa kaydeder. 4. aşamanın değişikliği ExposeSensitiveData'ya 1'i de ekler; böylece sonraki açılışlarda bu bilgi kaydedilir.

Disk numaraları hiçbir zaman kullanılmıyor, çünkü açılıştan açılışa değişiyorlar.

Windows: "running scripts is disabled"Windows: "running scripts is disabled"

You seeGördüğünüzWindows refuses to run IntelXe-EFI.ps1: "running scripts is disabled".Windows IntelXe-EFI.ps1'i çalıştırmıyor: "running scripts is disabled".

The fixÇözüm

  1. Start IntelXe-EFI.ps1 from a PowerShell window with this. It allows that one run only: 
    powershell -ExecutionPolicy Bypass -File .\IntelXe-EFI.ps1
  2. Downloaded the file with a browser? Run Unblock-File .\IntelXe-EFI.ps1 once.
  3. Mounting an EFI partition needs administrator rights (Restart as administrator).

Details: The Windows script.

  1. IntelXe-EFI.ps1'i bir PowerShell penceresinden şu komutla başlatın. İzin yalnızca bu çalıştırma için geçerlidir: 
    powershell -ExecutionPolicy Bypass -File .\IntelXe-EFI.ps1
  2. Dosyayı tarayıcıyla mı indirdiniz? Bir kez Unblock-File .\IntelXe-EFI.ps1 çalıştırın.
  3. Bir EFI bölümünü bağlamak için yönetici hakları gerekir (Restart as administrator).

Ayrıntılar: Windows betiği.

Other install.sh commandsinstall.sh'in diğer komutları

In the package folder (the app's Driver page has the same as buttons):

Paket klasöründe çalıştırın (uygulamanın Sürücü sayfasında aynı işler düğme olarak var):

CommandKomutWhat it doesNe yapar
./install.sh --statusCompares what is installed with this package and changes nothing.Kurulu olanları bu paketle karşılaştırır, hiçbir şeyi değiştirmez.
sudo ./install.sh --repairPuts back installed files that differ from the package and leaves the last backup alone.Kurulu dosyalardan paketle uyuşmayanları paketten yeniden kopyalar, son yedeğe dokunmaz.
sudo ./install.sh --uninstallRemoves the kexts and the Metal driver from /Library and keeps the backups.Kext'leri ve Metal sürücüsünü /Library'den siler, yedekleri saklar.
sudo ./install.sh --undoGoes back to what the last install replaced.Son kurulumun değiştirdiği dosyaları eski hâline getirir.

After --uninstall, remove IntelXe.kext from the EFI before you reboot.

--uninstall'dan sonra, yeniden başlatmadan önce IntelXe.kext'i EFI'den çıkarın.

Undo everythingHer şeyi geri almak

  1. The driverSürücüsudo ./install.sh --undosudo ./install.sh --undo
  2. The EFIEFIIntelXe.kext and SSDT-ARCOFF.aml out.IntelXe.kext ve SSDT-ARCOFF.aml'i çıkarın.
  3. RebootYeniden başlatın
  4. The extrasEklerIf you added them.Eklediyseniz.
  1. Undo the driver: sudo ./install.sh --undo.
  2. Remove IntelXe.kext and SSDT-ARCOFF.aml from the EFI: the app's EFI page (Undo), sudo ./efi.sh --undo, IntelXe-EFI.ps1's Undo last change..., or by hand. Each undo goes one change further back.
  3. Reboot.
  4. If you added them, also remove:
    • the system-volume copy: the Driver page's Safari and WebKit;
    • the Zink package: sudo ./install.sh --undo in its folder (it turns --global-gl off first);
    • the HiDPI modes: sudo ./hidpi.sh --off.
  1. Sürücüyü geri alın: sudo ./install.sh --undo.
  2. IntelXe.kext ve SSDT-ARCOFF.aml'i EFI'den çıkarın: uygulamanın EFI sayfası (Geri al), sudo ./efi.sh --undo, IntelXe-EFI.ps1'in Undo last change... düğmesi ya da elle. Her geri alma bir önceki değişikliğe döner.
  3. Yeniden başlatın.
  4. Eklediyseniz bunları da kaldırın:
    • sistem diski kopyası: Sürücü sayfasında Safari ve WebKit;
    • Zink paketi: kendi klasöründe sudo ./install.sh --undo (önce --global-gl'u kendisi kapatır);
    • HiDPI modları: sudo ./hidpi.sh --off.

The stage 2 settings stay in config.plist until you change them back.

2. aşamanın ayarları, siz eski hâline getirene kadar config.plist'te kalır.
